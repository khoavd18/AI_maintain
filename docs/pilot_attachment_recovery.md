# PM9 Representative Attachment Recovery

## Boundary Và Current Status

PostgreSQL lưu attachment metadata; `AttachmentStorage` lưu bytes dưới private
local root. PostgreSQL dump không chứa bytes. PM9 thêm bounded archive,
inspection và restore helpers nhưng không thêm object storage hay malware
scanning.

Focused synthetic filesystem tests đã cover non-empty archive, checksum,
missing/mismatch/orphan detection và containment. Checkpoint PostgreSQL-marked
suite trên disposable local PostgreSQL 16 `_test` đạt
`73 passed, 239 deselected`, trong đó test attachment:

- upload generated PDF qua normal API và nhận `201`;
- archive đúng một active attachment byte object;
- restore bytes vào isolated temporary root;
- download bằng restored storage + original `_test` metadata trả `200` và bytes
  khớp;
- Helpdesk download trả `403`;
- xóa restored bytes, soft-delete metadata qua API và unlink test archive.

Test không tạo/restore PostgreSQL dump và không chứng minh metadata/bytes
recovery từ một paired backup. Gate đó vẫn mở.

```text
NO-GO / NOT YET VERIFIED
```

## Fixture Bắt Buộc

- non-sensitive generated bytes, không dùng customer file;
- allowed PDF/PNG/JPG/JPEG signature, MIME, extension và bounded size;
- tạo metadata/bytes qua normal authenticated API path;
- unique PM9 namespace trên isolated `_test` database;
- checksum lấy từ committed application result;
- không commit fixture bytes;
- authorized reader và forbidden actor để kiểm tra download boundary.

Không tạo file trực tiếp trong storage root để giả lập successful upload.

## Paired Backup Procedure

1. Quiesce fixture mutations hoặc ghi một consistent pairing point.
2. Tạo PostgreSQL dump/checksum/manifest ngoài repository.
3. Liệt kê active attachment metadata tối thiểu cần thiết: opaque attachment ID,
   generated relative storage key, size và SHA-256; không đưa local path ra
   report.
4. Tạo bounded ZIP archive từ storage root bằng generated keys.
5. Inspect archive manifest, duplicate names, traversal/symlink và checksum.
6. Ghi database artifact ID và attachment archive ID vào cùng protected rehearsal
   record.
7. Không gọi backup pair là validated trước separate restore.

Archive helpers có size/file-count bounds, containment checks, temporary-file
publication và không tự xóa orphan. Checkpoint chỉ thực thi helper với generated
test bytes, không với pilot filesystem snapshot.

## Restore Procedure

1. Restore PostgreSQL vào database riêng kết thúc `_restore`.
2. Restore attachment archive vào empty isolated destination root.
3. Chạy aggregate integrity assessment:

```powershell
python -m src.reliability.attachments `
  --database-url-env DATABASE_URL `
  --storage-root "<isolated-restored-attachment-root>"
```

4. Expected counts: active metadata `>=1`, `ok_count` bằng active metadata;
   invalid key, missing byte, unreadable byte, checksum mismatch và orphan file
   đều bằng `0`.
5. Start FastAPI trỏ vào restored database/root.
6. Authorized actor download và checksum bytes; unauthorized actor nhận expected
   `401`/`403`.
7. Soft-deleted attachment không trở thành public/history rewrite.
8. Drop đúng restore database; xóa đúng destination, fixture records, archive
   và report paths được tạo bởi drill; xác nhận từng target. Không dùng generic
   recursive cleanup.

## Negative Cases

| Case | Expected behavior |
|---|---|
| Metadata có key traversal/absolute | Reject, không đọc ngoài root |
| Missing bytes | Aggregate missing count; download fail an toàn |
| Changed bytes | Checksum mismatch; không coi restore valid |
| Extra file | Orphan count; không tự xóa |
| Orphan metadata | Restore gate fail, điều tra paired artifacts |
| Unauthorized download | `401`/`403`, không trả bytes/path |
| Invalid archive member/symlink | Reject archive |
| Partial restore/publication | Không promote thành validated pair |

Failure report chỉ chứa aggregate count/code, không chứa storage key, absolute
path, file body hay reporter PII.

## Evidence Cần Để Pass

- exact test host/database/root identity ở dạng approved opaque label;
- upload/download HTTP statuses và role boundary;
- database dump + attachment archive identifiers/checksums;
- source/restored aggregate counts;
- restored checksum match;
- negative-case results;
- per-target removal và canonical-data-drift evidence;
- backup owner và database recovery contact approval.

Current local attachment storage vẫn là critical internal-pilot limitation.
No malware scan, object versioning, distributed transaction hoặc multi-host
storage claim được đưa ra. Xem [backup schedule](pilot_backup_schedule.md),
[backup/restore](backup_restore.md) và
[known limitations](known_limitations_acceptance.md).
